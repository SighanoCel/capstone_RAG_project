

project 1- Bank Customer Churn Prediction with Deep Learning

English project summary
1. Project Overview
This project predicts whether a bank customer is likely to leave the bank (customer churn) using a TensorFlow/Keras feed-forward
neural network. It also converts predicted churn probabilities into a retention-campaign analysis, estimating which probability
threshold could provide the best financial return under explicit business assumptions.
Questions addressed
• Which customer characteristics differ between customers who leave and those who stay?
• How should data be prepared for a neural network?
• How well does the model identify churners?
• Which customers should the bank prioritize for retention outreach?
• How can the potential return of a retention campaign be estimated?
2. Dataset and Target
The notebook uses 10,000 bank-customer records. The original target column Exited is renamed churn: 1 means the customer
left; 0 means the customer stayed. RowNumber, CustomerId, and Surname are removed before modeling.
Features include credit score, geography, gender, age, tenure, balance, number of products, credit-card ownership, active-member
status, estimated salary, satisfaction score, card type, and points earned. The notebook reports no missing values or duplicate rows
in its checks. Categorical variables are one-hot encoded with pandas.get_dummies(drop_first=True).
Potential target leakage: Complain has a Pearson correlation of about 0.9957 with churn. The notebook removes it because it may
reveal the target rather than generalizable churn patterns.

4. Data Preparation and Neural Network
• Split: 70% training and 30% test data, random_state=1 and stratified by target (7,000 training rows and 3,000 test rows before
resampling).
• Scaling: StandardScaler standardizes model inputs.
• Class imbalance: SMOTE is applied to training data only. With sampling_strategy=0.4, k_neighbors=2, and random_state=1,
counts change from 5,573 non-churners and 1,427 churners to 5,573 and 2,229.
• Architecture: Keras Sequential network with dense layers of 64 and 32 ReLU units, 20% dropout, L2 regularization, and one
sigmoid output neuron.
• Training: Adam optimizer, binary cross-entropy loss, recall metric, and 60 epochs.
• Output: probability between 0 and 1 representing estimated churn risk.

6. Retention Campaign ROI
The notebook groups predicted probabilities into 100 bins and estimates the result of contacting every customer whose score is at
or above each threshold. Assumptions: $3 per customer contact and $40 for each churner successfully retained.
Estimated return = (actual churners reached × $40) − (customers contacted × $3).
The break-even churn rate is $3 / $40 = 7.5%. Under these assumptions, contacting an additional group is economically worthwhile
if its expected churn rate is above 7.5%, provided the assumed benefit is realized.
The notebook's written report states that a threshold near 0.07 produced an estimated return of about $17,000 on the
3,000-customer test set. It reports contacting 1,833 customers and reaching 562 of 611 actual churners (recall 0.92, precision
0.31), compared with about $15,400 from contacting everyone. These are scenario estimates, not guaranteed real-world profits.
7. Deployment Artifacts
The model is intended for reuse by a Streamlit application at streamlit_app/bank_churn_app.py. The notebook saves:
• churn_keras_model.keras: trained neural network.
• churn_scaler.joblib: fitted StandardScaler.
• churn_features.json: exact feature order used during training.
The deployed application must use matching feature encoding and column order and apply the same fitted scaler before prediction.
The notebook also attempts to save an optional combined joblib bundle.
8. Important Technical Caveat
The notebook contains a scaling issue: it calls scaler.fit_transform(X_test) on test data. The correct procedure is to fit the scaler
on training data only, then use scaler.transform(X_test). Fitting again on the test set gives test features a different scaling basis
from training. Correct this and rerun predictions, metrics, score bins, and ROI calculations before relying on the results; the values
may change.
The ROI analysis assumes a fixed $3 contact cost and $40 benefit per successfully retained churner. It does not explicitly model
whether an intervention actually prevents churn, so real campaign results require validation.

5. Correlation and statistical tests on features
Bank Transaction Fraud Detection project – Pearson correlation (x100) between numeric features
and isFraud: amount −4.97; newbalanceOrig −11.94; oldbalanceOrg −11.99. No strong
correlation, so no sign of data leakage; all correlations are negative (lower amounts and balances
→ more fraud). The purpose of the check is to detect data leakage, i.e. an independent feature too
strongly correlated with the target, which would produce a biased, overfitted model.
Bank Transaction Fraud Detection project – Chi-squared test of independence (scipy
chi2_contingency) between each categorical feature and isFraud, using a contingency table
(crosstab). Formula: chi² = Σ (Observed − Expected)² / Expected; expected frequency = row total
× column total / grand total. Notebook results (p-value): CITY 0.09% → "no association" under the
threshold used; TYPE 0.00% → significant association; CARD TYPE 12.99% → no association; EXP
TYPE 0.09% → no association; GENDER 59.24% → no association.
Contingency table Gender vs isFraud: Female: 458,678 non-fraud, 92,504 fraud; Male: 414,111
non-fraud, 83,281 fraud. Proportions are almost identical (≈16.8% fraud for both genders),
consistent with the high p-value.
Bank Transaction Fraud Detection – page 3
Notebook conclusion: the only categorical feature associated with the target is type (p-value
0.00%, far below the threshold). A strong association between a feature and the target is good for
a predictive model; it is not data leakage because the transaction type is a characteristic of the
transaction itself, known at the time the fraud prediction is needed. Data leakage occurs when a
model uses information that would not be available in a real prediction scenario.
Analyst note: in the code the significance threshold is written as p > 0.05/100 (i.e. 0.0005 =
0.05%), not 0.05. This is why City and Exp Type (p = 0.09%) are labeled "no association",
whereas with the standard 5% threshold they would be significant. The notebook text mentions
a threshold of 0.05. Also, with over a million rows even tiny differences produce small p-values:
statistical significance does not imply practical relevance.

Interpretability

1. Project summary
The Car Performance Prediction project, by Celestin Signe Sighano, predicts the acceleration of a car (time
in seconds to reach a given speed, as recorded in the classic Auto MPG dataset) from two characteristics of
the vehicle: its fuel efficiency (mpg, miles per gallon) and its weight (in pounds).
The  project  has  three  goals:  (1)  build  a  regularized  linear  regression  model  (Ridge  regression)  to  limit
overfitting;  (2)  choose  the  regularization  strength  alpha  (lambda)  objectively  with  cross-validation  using
RidgeCV  instead  of  guessing  it;  (3)  explain  the  predictions  of  the  final  model  with  SHAP  (SHapley  Additive
exPlanations) to understand which feature drives the predicted acceleration.
Main  results:  the  Ridge  model  with  alpha  =  1  reached  a  test  RMSE  of  2.359  seconds;  the  cross-validated
RidgeCV  model  selected  alpha  =  5.0  and  reached  a  test  RMSE  of  2.360  seconds.  SHAP  analysis  showed
that  weight  has  a  strong  negative  impact  on  the  predicted  acceleration,  while  mpg  has  a  positive  impact  of
similar magnitude.
2. Dataset used in the Car Performance Prediction project
The data comes from the file mpg.csv (the well known Auto MPG dataset), loaded with pandas from Google
Drive in Colab. It contains 398 cars and 9 columns:
- mpg: fuel consumption in miles per gallon (from 9.0 to 46.6, std about 7.8)
- cylinders: number of cylinders (3 to 8)
- displacement: engine displacement (68 to 455)
- horsepower: engine power, stored as text because some values are missing and coded as '?'
- weight: vehicle weight in pounds (1613 to 5140, std about 846)
- acceleration: the target variable (8.0 to 24.8, std about 2.76)
- model_year: year of the model, from 70 to 82 (1970 to 1982)
- origin: region of origin coded 1, 2, 3 (1 = USA, 2 = Europe, 3 = Japan)
- name: car name (305 unique values, e.g. chevrolet chevelle malibu, ford torino)
Example rows: chevrolet chevelle malibu (mpg 18, 8 cylinders, weight 3504, acceleration 12.0); buick skylark
320 (mpg 15, weight 3693, acceleration 11.5); ford torino (mpg 17, weight 3449, acceleration 10.5).
3. Problem definition and feature selection
In the Car Performance Prediction project the task is a regression problem. The input features X are the two
numerical columns mpg and weight; the target y is acceleration.
Car Performance Prediction - Celestin Signe Sighano - page 1
Choosing only two features keeps the model simple and fully interpretable: each prediction can be
decomposed  into  the  contribution  of  fuel  efficiency  and  the  contribution  of  weight.  The  two  features  are
physically  meaningful:  heavier  cars  tend  to  be  slower  to  accelerate,  while  more  fuel  efficient  cars  in  this
1970-1982  dataset  are  usually  lighter,  smaller  cars.  Because  mpg  and  weight  are  strongly  correlated  with
each other, a regularized model such as Ridge is a sensible choice: the L2 penalty stabilizes the coefficients
when predictors are collinear.
The  horsepower  column,  which  contains  '?'  placeholders  for  missing  values,  was  not  used,  so  no  missing
value imputation was needed in this notebook.
4. Train/test split and feature scaling
The data was split with scikit-learn train_test_split using test_size = 0.3 and random_state = 101, giving 278
cars in the training set (70 percent) and 120 cars in the test set (30 percent). The fixed random_state makes
the results reproducible.
Feature scaling was performed with StandardScaler before training the Ridge model. Scaling is required for
Ridge  regression  because  the  L2  penalty  is  applied  to  the  size  of  the  coefficients:  without  scaling,  weight
(values in thousands) and mpg (values in tens) would be penalized very differently. The scaler was fitted only
on  the  training  data  (fit_transform  on  X_train)  and  then  applied  to  the  test  data  (transform  on  X_test).  This
avoids  data  leakage,  because  no  information  from  the  test  set  is  used  to  compute  the  mean  and  standard
deviation.
Example:  the  first  training  car  had  mpg  14.0  and  weight  4096,  which  became  -1.244  and  1.368  after
standardization (values expressed in standard deviations from the training mean).
5. Baseline Ridge regression model (alpha = 1)
Ridge regression is linear regression with an L2 regularization term: it minimizes the sum of squared errors
plus  alpha  (also  called  lambda)  multiplied  by  the  sum  of  the  squared  coefficients.  The  penalty  shrinks  the
coefficients  toward  zero  and  reduces  the  variance  of  the  model,  which  helps  against  overfitting.  Lasso,  by
contrast, penalizes the absolute value of the coefficients (L1 penalty).
In  the  Car  Performance  Prediction  project  a  first  Ridge  model  was  trained  with  alpha  =  1  on  the  scaled
training set, then evaluated on the scaled test set.
First  six  predictions  compared  with  the  real  acceleration  values:  predicted  16.13  vs  actual  16.5;  14.99  vs
17.8; 17.93 vs 17.9; 13.41 vs 12.5; 13.79 vs 12.0; 15.69 vs 12.8.
Evaluation  metric:  Root  Mean  Squared  Error,  RMSE  =  sqrt(mean_squared_error(y_test,  predictions)).  The
baseline Ridge model obtained RMSE = 2.359 seconds on the test set.
6. Choosing the hyperparameter alpha with cross-validation (RidgeCV)
A key question in the Car Performance Prediction project was: how can we be sure that alpha = 1 is the best
value  for  the  regularization  strength?  Instead  of  guessing,  the  author  used  cross-validation  with  scikit-learn
RidgeCV.
RidgeCV was configured with alphas = np.linspace(0.01, 5, 7), i.e. seven candidate values: 0.01, 0.84, 1.67,
2.51, 3.34, 4.17 and 5.0, and with scoring = 'neg_mean_squared_error'. RidgeCV trains the model for each
alpha, evaluates it with cross-validation on the training data only, and keeps the alpha with the best score.
Result: the best alpha selected was alpha_ = 5.0. The test RMSE of the RidgeCV model was 2.360 seconds,

practically  identical  to  the  baseline  (2.359).  The  final  standardized  coefficients  were  +0.584  for  mpg  and
-0.560 for weight.
Interpretation:  the  selected  alpha  is  the  upper  limit  of  the  search  grid,  which  suggests  that  an  even  larger
alpha  could  be  tested;  a  note  in  the  notebook  mentions  that  an  earlier,  wider  grid  found  alpha  =  10  as  the
best  value.  The  almost  unchanged  RMSE  shows  that  with  only  two  features  the  model  is  not  overfitting,  so
stronger regularization neither helps nor hurts much.
7. Model interpretation with SHAP (explainable AI)
To  interpret  the  predictions  of  the  RidgeCV  model,  the  Car  Performance  Prediction  project  uses  SHAP
(SHapley  Additive  exPlanations).  SHAP  values,  based  on  game  theory,  measure  how  much  each  feature
pushes an individual prediction higher or lower compared with the average (expected) prediction.
Implementation: the scaled training and test arrays were converted into pandas DataFrames with the column
names mpg and weight, so that the plots show readable feature names. A SHAP explainer was created with
shap.Explainer(model_cv,  scaled_X_train,  feature_names=...),  using  the  training  data  as  background,  and
the SHAP values were computed on the 120 test cars. The SHAP value matrix has shape (120, 2): one value
per  test  car  and  per  feature.  For  a  linear  model  like  Ridge,  the  SHAP  value  of  a  feature  is  its  coefficient
multiplied  by  the  difference  between  the  feature  value  and  its  background  mean,  so  the  explanations  are
exact.
Three  visualizations  were  produced:  a  SHAP  summary  (beeswarm)  plot,  a  SHAP  feature  importance  bar
chart  (mean  absolute  SHAP  value  per  feature),  and  a  SHAP  decision  plot  for  the  first  20  test  cars,  starting
from the explainer expected value.

1 Introduction 
The role of the logistics sector in modern supply chains is critical, as it facilitates the movement 
of goods in an efficient manner in an increasingly complex and dispersed market (Christopher, 
2016). As competition in the market is rising and the business environment is becoming more 
challenging in terms of reduced business margins, it is not only essential to make 
improvements in the business processes but also to develop a deeper understanding of the 
clients and their demands. 
With  the  rise  of  transactional  data,  there  is  an  opportunity  to  make  data-driven  decisions 
(Waller and Fawcett, 2013). However, there is still a lack of structural analytical frame work 
that enables businesses to comprehend client behaviour and make decisions in advance to 
maintain the business's stability and growth in the long term. Especially, comprehending the 
revenue generated from clients and its evolution over time is essential in maintaining business 
stability and growth. 
To  address  these  challenges,  this  study  aims  to  analyse  revenue  data  of  the  clients  of  the 
logistics firm and understand their behaviour over time. The clients are observed over a period 
of 36 months, allowing to analyse their behaviour over time. 
In contrast to traditional methods that view customer churn as a yes or no event, this study 
takes  a  behavioural  and  revenue-based  view (Neslin  et  al.,  2006).  It  does  not  just focus  on 
customer inactivity; it also looks at gradual declines in activity as early signs of disengagement. 
This difference is very important in business-to-business (B2B) logistics, where clients often 
decrease shipment volumes slowly instead of ending the professional relationship suddenly. 
Additionally, the analysis includes forward-looking indicators from predictive models (Verbeke 
et  al.,  2012).  By  blending  historical  performance  and transactions  with  short-term  forecasts, 
this  project  helps  identify  early  warning  signals  of  revenue  decline,  which  allows  for  timely 
intervention. 

2 Literature Review 
2.1 Logistics and Data-Driven Decision Making 
The role of logistics has transformed from an operational to a strategic function in supply chain 
management. This is because of the increasing complexity of the network and the variability 
of demand, which necessitate timely and informed decisions (Christopher, 2016). Thus, data 
analytics  is  an  essential  tool  in  enhancing the visibility,  performance  and responsiveness  of 
the logistics function (Waller and Fawcett, 2013): 
This can be attributed to the increasing adoption of data-driven decisions, which encompass 
various  forms  of  descriptive,  diagnostic,  predictive,  and  prescriptive  analytics  to  support

strategic decisions (Davenport and Harris, 2007). These types of decisions are essential in the

2.2 Revenue Concentration and Business Risk 
Revenue concentration is another common phenomenon in a business in which the majority 
of the revenue is generated by a small percentage of customers. This phenomenon is closely 
linked with the Pareto principle (Koch, 2008). However, this structure also poses risks because 
the business is now heavily dependent on a small number of clients. 
The risks posed by this structure can be quantified with the help of the Gini coefficient and the 
Lorenz  curve,  which  quantify the  inequality  in  value  distribution  (Cowell, 2011).  In  customer 
portfolio management, high concentration levels imply that a decrease in revenue is likely to 
be driven by a small number of economically significant customers. 
As shipment volumes are often dominated by a limited number of large accounts, 
understanding concentration is therefore essential for evaluating structural risk. 
 
2.3 Customer Churn 
Typically,  customer  churn  is  defined  as  the  termination  of  a  contractual  relationship,  with 
particular emphasis on subscription-based businesses (Neslin et al., 2006). However, in B2B 
environments, churn is more gradual. 
Recent research distinguishes between hard churn and soft churn, where declining 
engagement precedes full customer loss (Verbeke et al., 2012). This approach is better suited 
in  continuous  service  environments,  where  customers  may  reduce  activity  rather  than  stop 
suddenly. 
 
2.4 Revenue-Based Churn and Early Warning Systems 
As  customer  value  is  not  evenly  distributed,  revenue-based  churn  analysis  is  more  relevant 
than customer-based churn analysis (Fader and Hardie, 2009). This is because the loss of a 
few high value customers in the case of a high concentration portfolio would affect the overall 
revenue generated. 
Early  warning  systems  are  designed  to  address  this  problem  through  the  early  detection  of 
declining  customer  activity  using  behavioural  indicators  (Verbeke  et  al.,  2012).  This  is  very 
useful in the logistics sector because the volume of shipments is likely to be indicative of the 
customer’s demand patterns.

2.5 Customer Segmentation and Portfolio Analysis 
Customer segmentation is the process of grouping customers according to their characteristics 
and  behaviours (Wedel and  Kamakura,  2000).  This  is  very  useful  in  developing  appropriate 
marketing strategies. 
Portfolio analysis is another useful concept that helps firms segment their customers using the 
BCG  matrix  (Henderson,  1970).  This  matrix  is  useful  in  developing  appropriate  marketing

allocating resources effectively, especially in the case of heterogeneous B2B markets. 
 
2.6 Temporal Analysis and Seasonality 
Time  series  analysis  presents  a  framework  to  grasp  temporal  patterns,  such  as  trends, 
seasonality  and  volatility  (Hyndman  and  Athanasopoulos,  2021).  In  logistics,  seasonality  is 
relevant due to cyclical demand in sectors, such as retail and manufacturing. 
Failure to grasp these trends may cause an organisation to misinterpret customer behaviour. 
A  dip  in  activity  may  be  perceived  as  an  indication  of  declining  customer  base.  Therefore, 
temporal analysis is critical in distinguish between these trends. 
 
2.7 Prescriptive Analytics and Decision Support 
Machine learning and prescriptive analytics have been used in business settings due to their 
ability  to  analyse  data  with  intricate  relationships  (James  et  al.,  2021).  In  churn  prediction,

This  study  offers  a  comprehensive  analysis  of  revenue  dynamics,  customer  behaviour,  and 
risk exposure within a logistics company using a data-driven approach. 
The  findings  of  this  analysis  indicate  that  revenue  is  highly  concentrated,  with  20%  of 
customers  generating  93.8%  of  total  revenue.  This  is  an  indication  of  structural  fragility,  as 
performance depends on a limited number of high-value accounts. 
The analysis further indicates that revenue decline is primarily due to a progressive 
deterioration  among  existing  customers,  rather  than  complete  customer  loss.  A  significant 
number  of  clients  are  classified  as  “fading,”  indicating  that  revenue  loss  is  gradual  and 
potentially reversible. 
Risk is also unevenly distributed, being concentrated in specific sectors, geographic regions, 
and customer segments. Logistics and e-commerce sectors, as well as regions such as the 
Northwest, combine high exposure with elevated churn. 
Finally,  forecast  results  indicate  that  recent  performance  improvements  are  unlikely  to  be 
sustained, highlighting the urgency of proactive intervention. 
 
5.2 Key Insights 
The findings of this study lead to several key strategic insights: 
• Revenue  risk  with  a  limited  number  of  customers,  sectors,  and  regions  driving  both 
performance and vulnerability; 
• Churn is progressive, with most revenue loss occurring through declining activity rather 
than abrupt exit; 
• Performance is heterogeneous, requiring differentiated strategies across segments; 
• Future performance is at risk, reinforcing the need for proactive, data-driven 
management. 
 
5.3 Strategic Recommendations 
Based on the analysis, a set of targeted strategic recommendations is proposed. 
5.3.1 Prioritise High-Value Client Recovery 
Focus on high-value customers showing early signs of decline. 
Key actions include identifying the top 100–200 declining accounts, assigning senior account 
managers,  conduct  structured  reviews  to  diagnose  causes  of  decline  and  implementing 
targeted recovery measures such as pricing adjustments and service improvements.

5.3.2 Implement an Early-Warning System 
Establish  a  system  to  detect  early  signs  of  customer  deterioration  by  monitoring  revenue 
changes  and  use  forecast  signals  to  trigger  intervention  on  accounts  that  are  flagged.  This 
enables proactive intervention before full churn occurs. 
 
5.3.3 Develop Sector-Specific Strategies 
Differentiated strategies should be adopted across sectors. 
For high-risk sectors, retention-focused actions are required (pricing flexibility, service 
adaptation), whereas stable sectors should be prioritized for growth and expansion. 
 
5.3.4 Apply Geographic Targeting 
Regional  performance  difference  requires  differentiated  strategies.  Segment  regions  should 
be classified into recover, defend, and monitor categories. For ‘recover region’s (high churn 
and  high  loss), reviews should  be  conducted  at a  territory-level  and  local  sales  and  service 
presence should be strengthened. For ‘defend regions’, stable regions with high revenue, 
quality service should be prioritised and maintained, and unnecessary pricing pressure should 
be  avoided.  Performance  should  be  tracked  (but  without heavy investment) for the ‘monitor 
regions’. 
 
5.3.5 Focus on High-Impact Geography x Sector Combinations 
The most effective intervention occurs at the intersection of geography and sector.  Prioritize 
intervention  at  the  intersection  of  geography  and  sector,  where  revenue  loss  is  most 
concentrated. Assign clear ownership and implement targeted recovery plans. 
 
5.3.6 Improve Data Quality Monitoring 
Resolve data limitations, mainly the “Unknown” geographic category and implement monitoring 
systems to track customer behaviour, sector performance and regional dynamics. 
 
5.4 Managerial Implications 
The  results  underscore  the  need  for  moving  towards  a  data-driven  management  approach. 
Decision-making  should  focus  on  granular,  segment-level  insights  rather  than  aggregated 
indicators, enabling more effective resource allocation, churn reduction and revenue 
stabilisation.

5.5 Limitations and Future Work 
This  analysis  showed  several  limitations,  such  as  reliance  on  historical  data,  incomplete 
information and a forecast with uncertainties. Future research should be complemented with 
external data, improve forecasting models and apply advance machine learning techniques to 
improve predictive accuracy. 
 
5.6 Final Remarks 
As previously said, revenue decline is a result of identifiable structural and behavioural patterns. 
Through a focus on high-impact customers, sectors, and regions, and a proactive and data-
driven approach, the company can build resilience and sustain long-term performance.

project 5- HOUSE RENT PREDICTION PROJECT: MACHINE LEARNING PIPELINE DOCUMENTATION

DOCUMENT OVERVIEW AND CONTEXT
Project Objective: Predict house rental prices across multiple cities in India using a regression-based machine learning pipeline.
Target Variable: Rent (continuous numerical value representing monthly rent in INR).
Features Included: BHK (number of bedrooms, hall, kitchen), Size (square footage), Floor, Area Type, Area Locality, City, Furnishing Status, Tenant Preferred, and Bathroom.
Features Dropped: Posted On and Point of Contact. These features were removed because they do not carry predictive signal for the actual rental pricing and to prevent data leakage or overfitting.
EXPLORATORY DATA ANALYSIS AND OUTLIER CLEANING
Statistical Highlights: Initial data profiling showed a mean rent of approximately 34,993, with a minimum recorded value of 1,200 and an extreme maximum outlier of 3,500,000.
Feature Correlation: The target variable Rent has moderate positive linear correlations with Bathroom (0.441) and Size (0.413).
Outlier Removal Rules: First, properties where the size was small but the rent was disproportionately high (specifically, size under 3000 square feet with rent over 1,500,000) were removed. Second, properties where the size was extremely large but the rent was disproportionately low (specifically, size over 5000 square feet with rent under 500,000) were removed. Third, boxplot analysis of the Rent column highlighted extreme outliers. Properties with a monthly rent exceeding 650,000 were dropped to prevent distortion during model training. This systematic cleaning reduced the active dataset size from 4,746 records to 4,736 records.
CATEGORICAL DATA ENCODING STRATEGIES To prepare non-numeric features for regression modeling, two distinct encoding strategies were applied:
Mean and Target Encoding: Used for variables where the average rent acts as a representative category rank. This was applied to Area Type, Furnishing Status, and City. The process grouped the dataset by each category, computed the mean rent value for that category, rounded to two decimal places, and mapped it back to replace the original textual category. For instance, Mumbai's rent value mapping is significantly higher than Kolkata's.
Frequency Encoding: Used for high-cardinality nominal variables. This was applied to Floor, Area Locality, and Tenant Preferred. The process calculated the raw count of occurrences for each unique category within the dataset and mapped it to prevent the dimensionality explosion that would occur with one-hot encoding.
FEATURE SCALING AND COMPLEXITY OPTIMIZATION
Standardization: Because features had different ranges (for example, categorical frequencies versus encoded target values), a StandardScaler was applied to center features around a zero mean and unit variance. This stabilizes gradient steps and prevents any single feature from dominating.
Polynomial Feature Selection: Evaluated polynomial degrees from 1 to 9 using cross-validation with a split of 70 percent training and 30 percent testing. The process measured train and test Root Mean Squared Error (RMSE) at each degree. Based on the evaluation, a degree 3 polynomial was selected. Beyond degree 3, the test RMSE diverges significantly, indicating severe overfitting and a loss of generalization capability.
MODEL TRAINING CONFIGURATION AND PERFORMANCE METRICS
Model: Linear Regression configured with fit intercept set to False and positive coefficients forced to True, trained on 3rd-degree polynomial features.
Dataset Partitioning: 70 percent Training subset and 30 percent Testing subset, using random state 42.
Performance Evaluation Metrics: The Root Mean Squared Error (RMSE) is 21,837.96. The R-squared (R2) Score is 78.58 percent, demonstrating that approximately 78.58 percent of the variance in rental prices is explained by the engineered polynomial feature inputs. The RMSE to Average Rent Ratio is 65.79 percent (calculated as RMSE divided by Mean Rent multiplied by 100). Although the predictions are fairly robust, there is a moderate degree of variance indicating potential for further error reduction.
MODEL EVALUATION AND RESIDUALS
Residual Analysis: Evaluated by plotting prediction errors (actual rent minus predicted rent) against the actual rent values. The residuals plot is balanced around zero, showing stable predictions for typical rentals but displaying larger variances and under-prediction trends as rental values reach higher thresholds.
Alignment Visualizations: Subplots aligning transformed features alongside model predictions show that the polynomial curves match the localized density of rent values effectively.
Conclusion: The model is well-fitted, though predictions can be further refined. The model performs fairly and serves as a strong baseline that can be improved by testing advanced non-linear models or adjusting regularization parameters in future iterations.
